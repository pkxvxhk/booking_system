# Система бронювання (Django)

## Запуск

```
python -m venv .venv
.venv\Scripts\activate          # Windows
pip install -r requirements.txt
python manage.py migrate
python manage.py seed_demo      # демо-типи, особливості, кімнати
python manage.py createsuperuser
python manage.py runserver
```

Сайт: http://127.0.0.1:8000/  
Адмін-панель: http://127.0.0.1:8000/admin/

Листи (підтвердження, зміна статусу) виводяться в консоль runserver.

## Тести

```
python manage.py test booking
```

## Моделі

- RoomType — тип кімнати/місця
- Feature — особливість (проектор, Wi-Fi, ...)
- Room — кімната/місце: тип, вмістимість, ціна за годину, особливості, активність
- Booking — бронювання: кімната, користувач (необов'язково), ім'я, e-mail, початок/завершення, гості, статус, підтвердження e-mail, вартість

## Сторінки

| URL | Призначення |
|---|---|
| `/` | Список кімнат, фільтр за типом, кількістю гостей, вільним періодом |
| `/rooms/<id>/` | Картка кімнати та її зайняті періоди |
| `/calendar/` | Календар доступності на місяць, фільтр за типом |
| `/book/` | Форма бронювання з перевіркою доступності в реальному часі (тільки для авторизованих) |
| `/booking/<token>/` | Перегляд/скасування/оплата бронювання (власник або staff) |
| `/booking/<token>/pay/` | Імітація оплати бронювання |
| `/booking/<token>/confirm/` | Підтвердження через e-mail |
| `/my/` | Усі бронювання авторизованого користувача |
| `/my/active/` | Активні оплачені бронювання користувача |
| `/register/`, `/login/`, `/logout/` | Реєстрація / вхід / вихід (власні views, вихід лише POST) |
| `/api/availability/?room=&start=&end=` | JSON: чи вільний період, вартість, конфлікти |
| `/api/rooms/<id>/events/?start=&end=` | JSON: зайняті періоди кімнати |

## Логіка

- Статуси: pending, confirmed, cancelled. Періоди блокують pending і confirmed.
- Перетин перевіряється в `Booking.clean()` (працює і у формі, і в адмінці) та повторно в транзакції при створенні.
- Вартість = кількість годин * ціна за годину, рахується при збереженні.
- Бронювати можуть лише авторизовані користувачі. Деталі, скасування та оплата доступні власнику бронювання (staff бачить усі).
- Оплата імітується: кнопка "Оплатити" ставить `is_paid` і `paid_at`, надсилає лист. Адміністратор може позначити оплату вручну або дією "Позначити обрані як оплачені".
- Активні бронювання: оплачені, не скасовані, ще не завершені.
- Адмінка: CRUD кімнат/типів/особливостей, бронювань; дії "Підтвердити" / "Скасувати" з листом користувачу; при зміні статусу вручну теж надсилається лист.
